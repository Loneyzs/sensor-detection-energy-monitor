# MSPM0G3507 验证记录

项目采用 MSPM0G3507 核心板 + MotherBoard，OLED PA1/PA0，INA219 PB2/PB3，MOSFET PB14，单按键 PA30。业务参数：低功率0.30W、连续30秒、提醒5秒、启动宽限3秒，功率上限2.00W。

## 主机测试与构建

| 项目 | 结果 |
|---|---|
| 监测状态机 | 1W运行1小时得到1Wh；低功率连续计时、阈值相等、提醒取消、断电恢复、异常锁存与积分连续性通过 |
| 2W功率上限 | 1.999999W保持供电、2.000000W触发关断；启动宽限和提醒期间均生效；功率下降后保持锁存；按键恢复后仍超限则再次断电 |
| OLED与按键 | U/I/P/E/R、待机/提醒/异常/功率超限页面，按键消抖、保持和松开动作均通过 |
| OLED模拟总线 | 0x3C/0x3D寻址、显存分页、增量传输、失败重连通过 |
| INA219模拟总线 | 原始寄存器换算、符号电流、转换完成、错误阶段、超时与量程边界通过 |
| 动态错误检查 | 四组主机测试启用AddressSanitizer / UndefinedBehaviorSanitizer，通过 |
| 普通UART版本 | 构建通过，Flash 24264B / 128KB，RAM 10496B / 32KB |
| RTT调试版本 | 构建通过，Flash 31576B / 128KB，RAM 19016B / 32KB |

复现：`./scripts/test.sh`、`./scripts/build.sh`，以及 `ENERGY_BUILD_DIR="$PWD/build-mspm0-debug" ./scripts/build.sh -- -DEXTRA_CONF_FILE=debug.conf`。

## 新板实物验证

- SWD连接正常，工厂寄存器确认Flash128KB、SRAM32KB。两组GPIO I²C的开漏与输入使能配置已读回核对。
- 由底板外部电源供电，J-Link的3.3V供电线断开，仅保留PA19/SWDIO、PA20/SWCLK、GND，连接正常。本机J-Link使用固定VTref=3.3V设置，报告值不作为实际电压测量结果。
- 用户确认INA219逻辑供电3.3V。OLED实物正常显示；两路总线通信正常。
- 一次稳定运行快照：连续233次采集成功、零错误；12056mV、53500µA、644996µW，约225.3Ω。PB14高电平、OLED在线，状态RUNNING。
- 用户确认底板PA30按下、松开后可恢复供电；调低负载后提醒倒计时走完，负载实际断电，并手动测试其余原有流程基本正常。
- MCU复位后默认关闭负载，累计电量仅保存在RAM中。

上述带载验收完成于新增2W功率上限之前；新增保护已通过主机边界与状态流程测试。2W实物超限测试、数值精度与万用表对照仍可按README的68Ω功率电阻方案补充。

字体与OLED预览由生产渲染器生成，见 `tests/ui-previews/screens.png`。详细逐线连接及接口差异见 [接线表](MSPM0G3507接线表.md)。

## 后续负载异常排查

用户报告1kΩ／5W电位器在接近零阻值使用后无法测出阻值；随后出现电流接近零、母线电压下降和采集异常。当前将负载拆除进行检查：0x40为唯一应答地址，配置寄存器可读回0x3E67；电压ADC曾返回约11.8V，分流结果在零点附近，但转换完成轮询仍有间歇超时。通信正常不足以判定整个模块完好，仍需固定零输入及已知小电流负载验证。未确认故障归因；用户决定次日更换模块、使用固定功率电阻继续验证。原始调试日志保存在本地，不纳入公开仓库。
